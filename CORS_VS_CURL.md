# 🔍 Почему curl работает, а браузер нет?

## Ключевое различие

**CORS (Cross-Origin Resource Sharing) - это политика безопасности БРАУЗЕРА, а не сервера!**

## 📊 Сравнение

### curl / Postman / HTTP клиенты
- ✅ **НЕ подчиняются CORS** - это просто HTTP клиенты
- ✅ Могут отправлять запросы с любого Origin
- ✅ Сервер получает запрос напрямую, без проверки CORS
- ✅ Заголовок `X-Api-Key` работает без проблем

### Браузер (JavaScript fetch/XMLHttpRequest)
- ❌ **Строго соблюдает CORS** - это механизм безопасности браузера
- ❌ Проверяет Origin перед отправкой запроса
- ❌ Требует preflight (OPTIONS) для кастомных заголовков
- ❌ Блокирует запрос, если сервер не разрешает CORS

## 🎯 Как это работает

### curl запрос:
```bash
curl -H "X-Api-Key: ваш-ключ" http://192.168.31.75:7125/printer/status
```

**Что происходит:**
1. curl отправляет HTTP запрос напрямую
2. Сервер получает запрос
3. Сервер проверяет авторизацию (X-Api-Key)
4. Сервер возвращает ответ
5. ✅ **CORS не проверяется** - curl не браузер!

### Браузер запрос:
```javascript
fetch('http://192.168.31.75:7125/printer/status', {
    headers: { 'X-Api-Key': 'ваш-ключ' }
})
```

**Что происходит:**
1. Браузер видит кастомный заголовок `X-Api-Key`
2. Браузер понимает: "Это не простой запрос, нужен preflight!"
3. Браузер отправляет **OPTIONS запрос** (preflight)
4. Сервер должен ответить с правильными CORS заголовками
5. Если preflight не проходит - браузер **блокирует** основной запрос
6. ❌ **CORS проверяется браузером ДО отправки запроса!**

## 🔐 Почему так сделано?

CORS - это механизм безопасности для защиты пользователей от:
- XSS атак
- Несанкционированного доступа к данным
- Утечки информации между доменами

**Браузер защищает пользователя**, даже если сервер "разрешает" все запросы.

## 📝 Вывод

| Клиент | CORS проверка | Preflight | Почему |
|--------|--------------|-----------|---------|
| curl   | ❌ Нет       | ❌ Нет    | Не браузер, просто HTTP клиент |
| Postman| ❌ Нет       | ❌ Нет    | Не браузер, просто HTTP клиент |
| Браузер| ✅ Да        | ✅ Да     | Механизм безопасности браузера |

## 🎯 Для вашего случая

**curl работает**, потому что:
- curl не проверяет CORS
- Сервер получает запрос напрямую
- Авторизация через `X-Api-Key` работает

**Браузер не работает**, потому что:
- Браузер проверяет CORS
- Preflight (OPTIONS) не проходит
- Браузер блокирует запрос ДО отправки на сервер

**Решение:** Настроить Moonraker правильно обрабатывать preflight (OPTIONS) запросы через `cors_domains`.

## 💡 Аналогия

Представьте:
- **curl** = прямой звонок по телефону (без проверок)
- **Браузер** = звонок через секретаря (нужна проверка и разрешение)

Секретарь (браузер) проверяет, разрешен ли звонок, ДО того как соединить вас с нужным человеком (сервером).
