# 🔧 Решение для DHCP (динамический IP)

## Проблема
При DHCP IP адрес компьютера может меняться, и указывать конкретный IP в `cors_domains` неудобно.

## ✅ Решения

### Вариант 1: Использовать `*.lan` или `*.local` (рекомендуется)

В вашем конфиге уже есть:
```ini
cors_domains:
    http://*.lan
    http://*.local
```

**Проверьте, работает ли это:**
1. Откройте веб-интерфейс по адресу `http://ваш-компьютер.lan:3000` или `http://ваш-компьютер.local:3000`
2. Если работает - эти домены уже покрывают ваш случай!

### Вариант 2: Добавить несколько возможных IP адресов

Если знаете диапазон DHCP (например, `192.168.31.100-200`), можно добавить несколько:

```ini
cors_domains:
    http://localhost:*
    http://127.0.0.1:*
    http://192.168.31.100:*
    http://192.168.31.101:*
    # ... и т.д. для всех возможных IP
```

Но это неудобно, если диапазон большой.

### Вариант 3: Настроить статический IP для вашего компьютера

В настройках роутера или на компьютере:
- Зарезервировать IP адрес для вашего компьютера в DHCP
- Или настроить статический IP вручную

Тогда можно использовать один конкретный IP в `cors_domains`.

### Вариант 4: Использовать прокси/туннель

Запустить веб-интерфейс на том же устройстве, где Moonraker, тогда можно использовать `localhost`.

### Вариант 5: Попробовать паттерн с поддоменом

Попробуйте (может сработать, хотя Moonraker не любит wildcards):
```ini
cors_domains:
    http://192.168.31.*:*
```

Но Moonraker может выдать предупреждение.

## 🎯 Рекомендация

**Попробуйте сначала Вариант 1** - используйте `*.lan` или `*.local`:

1. Узнайте имя вашего компьютера:
   ```cmd
   hostname
   ```

2. Откройте веб-интерфейс по адресу:
   - `http://имя-компьютера.lan:3000`
   - или `http://имя-компьютера.local:3000`

3. Если это работает - `*.lan` и `*.local` уже покрывают ваш случай, ничего добавлять не нужно!

## 📝 Текущая ситуация

В вашем `moonraker.conf` уже есть:
```ini
cors_domains:
    http://*.lan      # ✅ Должно работать для DHCP
    http://*.local    # ✅ Должно работать для DHCP
```

Попробуйте открыть интерфейс через `.lan` или `.local` домен вместо `localhost`!
